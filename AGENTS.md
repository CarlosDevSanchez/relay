# AGENTS.md

Canonical guide for any coding agent (Claude, Codex, ...) and human contributors. **Read [docs/STATUS.md](docs/STATUS.md) first for the current state.** Keep it current: every phase updates AGENTS.md, README.md, ROADMAP.md and docs/STATUS.md (and CLAUDE.md if needed).

## What Relay is
Electron + React + Tailwind + xterm + node-pty desktop app (macOS primary, Linux second, bun). It runs the OFFICIAL `claude` (and `codex`) CLI in a PTY per account so a developer can continue the same session on another of their own accounts of the SAME provider when one runs out of quota (handoff of the session transcript). Claude <-> Codex handoff is post-MVP and refused.

## Non-negotiable rules
1. Only spawn the official CLIs, in a PTY. No chat UI on stream-json / Agent SDK.
2. Never read, extract, forward or log credentials, tokens or secrets. Never call undocumented endpoints or provider APIs. The only network call Relay makes itself is the update check: a GET to the public GitHub Releases `latest` endpoint of its own repo (`CarlosDevSanchez/relay`), automatic check: packaged app only, 10 s after startup and every 6 h, off with pref `updates.check`; manual check only on a click in Settings; nothing is sent but the request (`src/main/updates.ts`). A newer version only shows a modal; the release URL is built in main from the validated `x.y.z` (GitHub's `html_url` is ignored) and opened in the browser by an explicit click.
3. Never switch accounts automatically. Every switch is an explicit user click/confirm. Relay never sends input on its own initiative except the auto-continue prompt (pref `handoff.autoContinue`, default on) as argv after a user-confirmed handoff (`claude --resume <id> <message>` / `codex resume <id> <message>`, message a separate argv element, no shell; `providers.*.resumeArgs`; message validated by `checkContinueMessage`: 1-500 chars, no control chars, no leading `-`, not a single ASCII word). What reaches the pty is only: user keystrokes in the terminal and the user-pasted login code; (F6.3, Claude chat) the text the user submits in the composer, as a bracketed paste + Enter in one write (`pty:send`; main strips C0 controls except `\n`/`\t`, DEL, C1 and ESC, `src/main/bridge.ts`), only on the user's explicit send and only when the classified screen is `idle` (the renderer reads the xterm frame after it parsed all received output; main refuses the write with `stale` when more output arrived than the renderer had parsed, seq guard in `pty.ts`; the pty must be a live Claude session); Stop = exactly one `\x1b` (`pty:stop`); and the clear sequence (`\x15`, preceded by `\x1b` when a `/` or `@` list is open; `pty:clear`, fixed allowlist) after an in-app confirmation, refused while the CLI is mid-turn (the send that follows a confirmed clear goes through the same gates). (F6.4, Claude chat) answering a CLI dialog (permission, AskUserQuestion, review, plan) ONLY by an explicit click (or a digit key on the focused card or one of its option buttons) on a prompt-card button, as one action of a closed allowlist (`pty:answer`, `AnswerAction`, `checkAnswer`): a digit 1-9 (select / toggle), Tab (next tab), `\x1b` (cancel), or for a text row the digit ALONE, after which the renderer re-reads the screen and only if the same dialog shows that row selected (nothing else changed) sends the line (no controls, no ESC, no paste markers) + `\r`, which main accepts only right after that digit (any other write on the pty cancels the wait). The card is built from the classified screen over the whole viewport (a dialog whose top rule is not on screen, a non-contiguous option list, or labels that disagree with the transcript get no answer buttons); its buttons arm only after its fingerprint was stable for 400 ms; immediately before writing the renderer flushes xterm, re-classifies and compares kind + fingerprint with the card (mismatch: nothing is sent); main refuses with `stale` when more output arrived (seq guard) and allows ONE answer per frame (`seq`); one shot per card, no retries, no queued keys. (F6.5, Claude chat) slash commands and `@file` mentions go ONLY as composer text through the same `pty:send` (one bracketed paste + Enter, trailing whitespace trimmed; Relay never types a bare `/` or `@`): the `/` palette and `@` autocomplete only fill the composer, and the controls row sends complete `/compact`, `/clear` (after an in-app confirmation) and `/model <opus|sonnet|haiku|default>` (after a dialog saying it changes the account's default model) the same way, only from an `idle` screen on an explicit click; a bare picker command (`/model`, `/permissions`, ...) switches the view to the terminal after the send. One more key exists: `pty:key(ptyId, seq, 'shift-tab')` (closed allowlist `KEYS` in `bridge.ts`, `checkKey`, seq guard) = `\x1b[Z`, sent one press at a time from the mode dropdown only on an explicit click, only when the screen is `idle`, after re-reading the CLI footer before each press (stops at the target, after 4 presses, or opens the terminal when the footer is unreadable or did not change); switching to Auto, or to any mode whose forward path crosses Auto (Plan or Accept edits to Manual), asks first (`passesAuto`); if the cycle stops while the CLI sits in Auto and Auto was not the target, Relay opens the terminal with a persistent error. `files:list` is capped (2000 dirs, 2000 files, depth 5), skips build output dirs and is cached 5 s per pty. `files:list` lists file names of the tab's own project (no dot entries, no node_modules, no symlinks out of the project, no contents). Relay never writes `\x03`, `\x04` or `\x1a`, never answers any other dialog (folder trust, `/model`, unknown: terminal) and never replies to a prompt by itself. Dialogs that can appear on their own (limit modal) focus the safe button (`data-autofocus`), never a switch.
4. Imported dirs are never deleted and are only modified through the explicit consent flows (shared-memory link, with a dialog naming the dir).
5. Never bundle or redistribute the CLI. Install only through the official installer, after a main-side confirmation showing the exact command; Relay downloads nothing itself. That includes Relay's own updates: it never downloads or installs a new Relay (no electron-updater; the app is ad-hoc signed), it only opens the release page so the user downloads and replaces the app by hand.
6. The MCP view never exposes env, headers, args, tokens or URL userinfo/path/query (redaction happens in main, `src/main/mcp.ts`; tested with planted secrets).
7. Never lose user data: back up before replacing, move atomically, never overwrite differing content.
8. No `window.prompt/confirm/alert` (Electron does not implement them): use the in-app modal (renderer) or main-side `dialog.showMessageBox`.
9. Usage (F5.1): the only way Relay reads the official Claude usage is the CLI's own status line JSON (`rate_limits`), through Relay's script (`<RELAY_HOME>/bin/statusline.sh`) passed with the official `--settings` flag as inline JSON, only for Claude new/resume/handoff ptys (never login/install). Relay never edits a user settings file: `<configDir>/settings.json` is only READ for its `statusLine.command`, which the script chains (env `RELAY_USER_STATUSLINE`, same JSON on stdin, its output is what the CLI shows). The script only writes `<RELAY_HOME>/status/<accountId>.json` (private dir, atomic) and prints; main parses only the rate-limit windows, and only the windows reach the renderer. The chained user command runs under `/bin/sh`; its `refreshInterval` / `padding` are copied into the inline `--settings`. Pref `usage.statusLine` turns the injection off.
10. History (F5.1): the sidebar lists only sessions in `<RELAY_HOME>/sessions.json` (registry). Removing an entry never deletes a transcript. History IPC (`history:*`) is validated by `checkSessionRef`.
11. The renderer only sends ids/intent; commands, paths and env are built in main (`validate.ts` checks every IPC input).

## Architecture
- `src/main/` (pure logic, no Electron imports unless noted): `paths` (cwd encoding, default-install detection, candidate dirs), `store` (accounts/projects/copies JSON), `env` (CLAUDE_CONFIG_DIR / plain env, PATH fix), `providers` (claude/codex definitions, official install command), `sessions` (transcript listing; Claude here, Codex in `codex`), `codex` (Codex rollout layout: find/list sessions, title/cwd, usage-limit parsing and scan, new-session discovery), `handoff` (copy a session to another account, terminate source), `limit` (tail transcript, detect `rate_limit`, parse reset), `usage` (auth status + local 5h tokens), `shared` (global memory symlinks), `catalog` (skills/agents/commands listing), `mcp` (redacted MCP report), `cli` (version detection), `updates` (pure: GitHub Releases `latest` check, SemVer compare, release URL built from the version), `prefs` (notification + handoff + usage + updates prefs, `checkContinueMessage`, `checkWarnAt`), `rates` (status line script, `--settings` args, usage tracker with warnings), `registry` (Relay's session history), `transcript/` (F6.1, Claude only: `parse` allowlist parser of transcript lines into `TEvent`s grouped by `message.id`, ordered by byte offset, unknown lines ignored; `session` pages from the end of the file, reuses `limit.tailFile` for live batches `session:events` with `seq`, subagent threads read on demand; `src/shared/transcript.ts` `applyBatch` is the idempotent renderer reducer; IPC `session:subscribe|unsubscribe|older|subagent` takes only account/cwd/session/agent ids, `validate.checkTranscriptRef`), `validate` (IPC input checks), `bridge` (composer/Stop/clear bytes, F6.3), `src/shared/screen.ts` (pure screen classifier, oracle `tests/fixtures/screens/README.md`), `pty` (node-pty, Electron-free), `index.ts` (Electron window + typed IPC; only place using `app`/`dialog`).
- `src/preload/index.ts`: contextBridge exposing `RelayApi`.
- `src/shared/types.ts`: types shared by main, preload and renderer.
- `src/renderer/`: `Chat` (F6.3 composer, activity line, info row; classified screen via `screens.ts` from the hidden xterm), `App` (state, tabs, modals), `Onboarding`, `Login` (login panel), `Sidebar` (compact/expandable account cards, collapsible sections, projects, sessions; collapse containers use `overflow-clip`, never `hidden`, ; the app shell (html, body, #root, root div) is `overflow: hidden` and e2e (including a long-label real-data scenario, `sidebar-realdata.png`) asserts, in every sidebar state and at 900 px, that nothing leaves the sidebar box, nothing overflows its own box unless it truncates with an ellipsis, and the page never scrolls sideways, even after focusing every focusable; it also checks the main area never overflows, with and without a tab open), `Settings` (large modal), `Conversation` (F6.2 chat view of a Claude session: `createFeed` in `src/shared/transcript.ts` keeps one state per tab; timeline of messages, tool cards, diffs, lazy subagent threads, notices; `content-visibility: auto` + paging instead of virtualization; it is the default view of Claude tabs, with a Chat/Terminal toggle in `App`; the terminal stays mounted but hidden with `visibility`; Codex tabs are terminal only), `md` (markdown via `marked`'s lexer rendered straight to React elements plus `highlight.js` core with 9 languages, also as elements: transcript text is never set as HTML, raw HTML shows as text, images as alt text, links are inert), `Terminal` (xterm, theme derived from the daisyUI theme), `ui` (Dialog with `data-autofocus`, modal helpers, Dropdown, toasts as a top-layer popover; errors and backup-path toasts stay until dismissed), `status`. UI stack: Tailwind 4 + daisyUI 5 (`@plugin "daisyui"` with our own `relay-light`/`relay-dark` themes in `styles.css`; no custom .btn/.card CSS, use daisyUI components and theme colors). All dialogs are native `<dialog>` via `ui.Dialog`; CSP allows `data:` images (daisyUI icons). xterm 6 draws on a canvas, so e2e cannot assert terminal text from the DOM. contextIsolation + sandbox, no nodeIntegration.
- `tests/` vitest (fixtures in temp dirs); `e2e/smoke.mjs` Playwright-Electron smoke.

## Providers
- `claude`: `CLAUDE_CONFIG_DIR`, `claude auth login|status --json`, `claude --session-id <id>` (Relay picks the id) / `--resume <id> [message]`, transcripts `projects/<enc cwd>/<id>.jsonl`, shared memory = CLAUDE.md + skills/agents/commands + project memory.
- `codex` (codex-cli 0.164.0, docs/spikes/F5.md): `CODEX_HOME` (always set, `~/.codex` included: same install, auth is `auth.json` in the home), `codex login`, `codex login status` (exit 0 logged in / 1 not; no email/plan), new session = bare `codex` (the CLI assigns the id; Relay binds the tab to the first new rollout of the cwd, `providers.codex.assignsId = false`), `codex resume <id> [message]` (same argv rules as Claude), rollouts `sessions/YYYY/MM/DD/rollout-<ts>-<id>.jsonl` (cwd in line 1, title = first `UserMessage` item), usage limit = `codex_error_info: "usage_limit_exceeded"` in `task_complete.error`. Only top-level threads count (`session_meta.source` a plain string and `thread_source` "user"; multi-agent child rollouts have an object source / `parent_thread_id`, cannot be resumed, and are ignored by listing, tab binding and handoff; a tab binds only to `originator: codex-tui` (real TUI: `source: "vscode"`, IDE extension is `codex_vscode`, exec `codex_exec`); rollouts without `source` (very old Codex) are not listed or bound; window: an outside TUI on the same home+cwd before the tab's first prompt can be bound). Handoff copies the rollout to the same relative path in the target home (SQLite index not needed), requires the recorded cwd to be the project and refuses symlinked path components. Imported dirs are probed (`claude auth status`, `codex login status`) only when that creates no files: `.claude.json` / `config.toml`, `installation_id`, `state_*.sqlite` or `sessions/` present (`canProbe`), else the status is `unchecked`. Shared memory = `AGENTS.md` only. Install: `if command -v brew ...; then brew install --cask codex; else npm i -g @openai/codex; fi` (confirmed main-side). Parent `OPENAI_API_KEY`/`CODEX_API_KEY`/`CODEX_ACCESS_TOKEN` are stripped from the child env.
- Handoff only between accounts of the same provider (`checkHandoff` refuses the rest: "Claude ↔ Codex llegará después del MVP").

## Data locations
`~/.relay` (override with `RELAY_HOME`): `accounts.json`, `projects.json`, `prefs.json` (`notifications: {system, sound}`, `handoff: {autoContinue, message}`, `usage: {statusLine, warnAt}`, `updates: {check (default true), skipped ('' or x.y.z)}`), `sessions.json` (registry: `{provider, accountId, sessionId, cwd, createdAt, lastActiveAt, origin: new|resume|adopt, handoffs: [{from,to,at}]}`; recorded on new/resume/handoff/`/clear` rebind/adopt, lastActiveAt on pty output at most once a minute; no migration), `bin/statusline.sh`, `status/<accountId>.json`, `copies.json` (handoff copy records), `shared/` (global memory: `CLAUDE.md`, `skills/`, `agents/`, `commands/`, `projects/<encoded cwd>/memory/`), `backups/<account>/<timestamp>/` (content replaced by linking), `accounts/<id>/` (managed account config dirs).

Accounts map to `CLAUDE_CONFIG_DIR=<account configDir>`. Exception: a dir resolving to `~/.claude` is the default install (`defaultInstall`): plain `claude` keeps config in `~/.claude.json` with its own keychain entry, so Relay runs it WITHOUT `CLAUDE_CONFIG_DIR` (data paths still use `~/.claude`; MCP config is read from `~/.claude.json`).

Transcripts: `<configDir>/projects/<cwd with every non-alphanumeric char -> '-'>/<session-id>.jsonl` (+ sibling `<id>/` dir). Rate-limit line: `{"type":"assistant","isApiErrorMessage":true,"error":"rate_limit","apiErrorStatus":429,"message":{"model":"<synthetic>","content":[{"text":"You've hit your session limit · resets 1:10am (America/Bogota)"}]}}`. Details: docs/spikes/F0.md.

## Commands
```
bun install          # postinstall fetches Electron and rebuilds node-pty
bun run dev          # electron-vite dev
bun run typecheck
bun run test         # vitest
bun run coverage     # v8 coverage of pure src/main modules
bun run build
bun run dist:mac     # electron-builder: ad-hoc signed arm64 Relay.app + dmg/zip in dist/ (README "Build for macOS"); RELAY_E2E_APP=<binary> node e2e/smoke.mjs runs the smoke against it
# Release: bump package.json (SemVer 0.x) in `chore(release): vX.Y.Z` on dev, PR to main, tag vX.Y.Z on main; .github/workflows/release.yml (scripts/release-guard.sh) builds and creates a DRAFT GitHub release, the owner publishes it. CI: .github/workflows/ci.yml.
bun run e2e          # builds, then drives the app with Playwright against a stub `claude` in a temp RELAY_HOME/HOME; never touches real data; the smoke sets RELAY_E2E_BACKGROUND=1 (window invisible, shown inactive, no dock icon, no focus steal, `backgroundThrottling: false` so the hidden window keeps painting; only affects visibility)
```

## Workflow
- Work on feature branches merged into `dev`; `main` is protected (PR + owner approval).
- Each phase: implement -> independent audit -> fix, repeat until no BLOCKER/MAJOR. One commit per phase.
- Bug fix = failing regression test first; new code = tests. Never lower coverage thresholds.
- Verify GUI changes with the e2e smoke, not only unit tests (the `window.prompt` bug shipped because unit tests could not see it).
- Before pushing, reproduce CI locally.
