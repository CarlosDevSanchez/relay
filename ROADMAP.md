# Roadmap

Relay only spawns the official CLIs in a PTY. Accounts are never switched automatically: every switch is an explicit user confirmation.

- **F0 spikes** (done, docs/spikes/F0.md): `claude auth status` shape, login flow, transcript usage / rate_limit lines, no official usage command.
- **F1 base** (done): multiple terminals (tabs), official login (`claude auth login`), rename/remove account, account status cards (plan, limit, local 5h tokens).
- **F2 limit detection** (done): live detection by tailing the session transcript, reset-time parsing, system notification + modal with a confirm-only switch ("Continuar en ...") or "Esperar al reinicio" (reminder notification only), notification prefs store.
- **F3 shared global memory** (done): `~/.relay/shared` (`CLAUDE.md`, `skills/`, `agents/`, `commands/`, `projects/<enc>/memory/`) symlinked into each opted-in Claude account dir; never credentials, `.claude.json`, settings or history. F5 adds `AGENTS.md` for Codex accounts.
- **F4 settings panel** (done): accounts, notification prefs, skills/MCP read-only. Detect missing official CLI (`claude`, later `codex`) and offer an Install button that, after user confirmation, runs the provider's official installer visibly in the embedded terminal (Claude: `curl -fsSL https://claude.ai/install.sh | bash`). Relay never bundles or redistributes the CLI. **UX: onboarding + dashboard** (done): in-app modal instead of `prompt()/confirm()` (unsupported in Electron), onboarding for 0 accounts (CLI check, new login or import of `~/.claude*`, optional project), sidebar with account cards/projects/sessions, explicit "Continuar en otra cuenta" menu, `RELAY_HOME`, Playwright e2e smoke (`bun run e2e`).
- **F4.1 UI: daisyUI + auto-continue** (done): renderer on daisyUI 5 with own themes, settings as modal, guided login panel, toasts, xterm themed from the active theme; after a user-confirmed handoff the target starts with `claude --resume <id> <message>` (pref `handoff`, default on, Codex unsupported -> no message).
- **F5 Codex** (done, docs/spikes/F5.md): Codex accounts (managed `CODEX_HOME` under `~/.relay/accounts/<id>` or imported, `~/.codex` included), `codex login` tab, `login status` probe, session listing from rollouts (title = first user message, project by recorded cwd), resume and handoff between Codex accounts with auto-continue (`codex resume <id> <message>`), usage-limit detection from `usage_limit_exceeded` events, shared `AGENTS.md`, official install (brew cask or npm). Cross-provider handoff stays refused. **Unverified** (no Codex login was done): the interactive login flow, the logged-in `login status` output, real quota wording incl. the same-day reset format (verified against a stub backend only), the on-disk shape of sub-agent rollouts (from binary strings), keyring credential store.
- **F5.1 Consumo e historial** (done): official usage bars (Claude: status line JSON via the official `--settings` flag with a Relay script that chains the user's own status line; Codex: `token_count.rate_limits` when present), warning per window at a configurable threshold, 100% = limited; project history = only what was done in Relay (`sessions.json`, "Abrir sesión existente…", "Quitar del historial de Relay"); onboarding defaults to Codex when it is the only CLI installed; logo wired (window/dock icon, sidebar, onboarding, favicon). **Unverified**: the real Codex `rate_limits` shape, usage bars with a real Pro/Max account.
- **F5.2 Compact cards** (done): account cards compact by default (dot, name, plan/provider badges, two thin 5h/7d bars; details on expand), collapsible "Cuentas" (one dot per account) and "Proyectos" sections, state in localStorage; F5.1 audit follow-ups (best-effort registry writes, registry-filtered title-cached history listing, `auth status` only when the 100% state flips, chained status line keeps `refreshInterval`/`padding`, brand colours teal #69C4CF / navy #1A262C).
- **F6 Vista enriquecida** (in progress, plan in docs/design/F6-vista-enriquecida.md): chat-first view: the official CLI keeps running in its PTY (hidden by default, always alive and one click away); the chat is built from the transcript the CLI writes, messages go in through the composer (bracketed paste into the PTY) and the CLI's prompts are read from the terminal screen and shown as cards with buttons. F6.0 research spike done (docs/spikes/F6.md, fixtures in tests/fixtures/transcript/); F6.1 transcript parser and event model done (audit fixes applied); F6.2 conversation view done (its interim Terminal/Dividida split was replaced by Chat/Terminal in F6.3) (marked + highlight.js, e2e with a scripted transcript); F6.0b screen/keys spike done (docs/spikes/F6b.md, fixtures in tests/fixtures/screens/); F6.3 chat-first core done (hidden-but-live terminal, screen classifier, composer bridge, Stop, activity line, rule 3 amended); F6.4 prompt cards done (permission, AskUserQuestion with review, plan; fingerprint + seq guard, closed key allowlist, rule 3 amended again); next: F6.5 controls bar + `/` and `@` palettes, F6.6 polish, F6.7 Codex.
- **Post-MVP**: Claude <-> Codex brief; packaging.
